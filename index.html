1. Architecture

NOVA is a stack-based processor. There is no general-purpose register file. Computation happens on hardware-managed stacks. Instructions are variable-length (1–9 bytes): common operations are a single byte, longer encodings only when immediates or addresses are needed.

Why a stack machine?

  • Denser code: average instruction is ~1.6 bytes vs 4 bytes for fixed-width RISC
  • Zero-operand ALU: ADD pops two values, pushes the result — no register fields to encode
  • Simple compilers: expression trees map directly to stack operations
  • Fast context switches: minimal architectural state to save/restore

The Four Stacks

StackPointerWidthPurpose
Data StackDSP64-bitOperand stack for all computation
Call StackCSP64-bitReturn addresses + saved frame pointers
Exception StackESP64-bitTrap frames
Vector StackVSP128-bitSIMD operands

Each stack has a hardware limit register. Pushing past the limit triggers a StackOverflow trap; popping an empty stack triggers StackUnderflow.

Registers (few!)

Most state lives on stacks. The register file is minimal:

RegisterPurpose
DSP CSP ESP VSPStack pointers
PCProgram counter
FPFrame pointer (indexes locals on data stack)
STATUSPrivilege level, interrupt mask, NZCV flags
CAUSE EPC TVALTrap cause, exception PC, trap value
SATPPage-table root + address-space ID
CYCLE TIMERead-only counters

Modern Features

  • SIMD: 128-bit vector stack, 4×32-bit / 2×64-bit lanes, predicated ops, gather/scatter
  • Crypto: hardware AES round, AES key expansion, SHA-256 compression, hardware RNG
  • MMU: 3-level page tables, 4KB/2MB/1GB pages, 48-bit physical addresses
  • Privilege: 4 levels (User/Supervisor/Hypervisor/Machine) with trap delegation
  • Atomics: LR/SC + AMOADD/AMOSWAP/AMOAND/AMOOR
  • Debug: hardware breakpoints, watchpoints, instruction trace, EBREAK
  • Perf: 8 programmable counters (cycles, instructions, cache/TLB misses, branch mispredicts)

2. Instruction Set

Variable-length, 1–9 bytes. First byte is the opcode; immediates follow little-endian. Opcode space is organized by category:

RangeCategory
0x00–0x3FStack manipulation (PUSH, POP, DUP, SWAP, ROT, ENTER, LEAVE…)
0x40–0x7FInteger ALU — zero-operand (ADD, SUB, MUL, DIV, AND, SHL, CMP…)
0x80–0x9FMemory (LOAD8/16/32/64, STORE, MEMCPY, atomics)
0xA0–0xBFControl flow (JMP, BZ/BNZ/BEQ/BNE, CALL, RET)
0xC0–0xCFSystem (ECALL, EBREAK, CSR access, FENCE, RDTIME)
0xD0–0xDFFloating-point (FADD.D, FSUB.D, FMUL.D, FDIV.D, conversions)
0xE0–0xEFVector/SIMD (VADD.4S, VLOAD, VSTORE, VSEL…)
0xF0–0xFFCrypto (AESENC, SHA256C, RDRAND, CPUID)

Example: function call

; add(a, b) — args pushed by caller, result left on stack
main:
    PUSH8  40
    PUSH8  2
    CALL   add
    WFI            ; halt

add:
    ENTER  0       ; build frame (no locals)
    LOADL  1       ; push arg1
    LOADL  0       ; push arg2
    ADD            ; pop, pop, push sum
    LEAVE
    RET

3. Microcode

Every NOVA instruction decomposes into micro-operations (register transfers). Simple instructions are single-uop; complex ones expand:

  • ADD → DPOP T0; DPOP T1; ALU ADD T0,T1,T0; DPUSH T0
  • ENTER n → CPUSH FP; FP←DSP; DPUSH 0 (×n)
  • CALL off → FETCH16 T0; CPUSH PC; PC←PC+T0
  • MEMCPY → 8-byte chunk loop + byte tail loop
  • SHA256C → 64-round compression (or native crypto intrinsic)
  • Trap entry → push STATUS/PC/CAUSE/TVAL to exception stack, elevate privilege, jump to vector

The VM implements these as inline Swift sequences — no separate ROM needed — but the decomposition is normative: MICROCODE.md

4. iOS VM App

A SwiftUI app that emulates the NOVA CPU on Apple Silicon iPads and iPhones.

What it does

  • Opens to a blank menu with a single firmware toggle
  • When firmware is on: choose built-in default or custom firmware (via Files app)
  • Load programs (.bin files) via the Files app document picker
  • Runs the VM on a background thread with a live console (green-on-black terminal)
  • Stop / Reset / Close controls; register and status readout
  • Console I/O via memory-mapped address 0xFFFF_FFFF_FFFF_0000

Architecture of the app

FileRole
NovaCPU.swiftFetch-decode-execute loop. Inlinable stack primitives, @inline(__always) hot paths, ContiguousArray memory.
NovaMemory.swiftGuest RAM: single flat array, stack regions at top, MMIO console hook.
NovaFirmware.swiftDefault firmware image + custom firmware loader (security-scoped Files URLs).
NovaVMEngine.swiftOwns CPU+memory, background thread, publishes console text to SwiftUI.
MenuView.swiftBlank menu: firmware toggle, file pickers, Run button.
VMView.swiftRunning VM: console, Stop/Reset, status.

Apple Silicon optimization

  • VM runs on a dedicated Thread at .userInitiated QoS — never blocks UI
  • Memory is a single ContiguousArray<UInt8> for cache-friendly sequential access
  • Hot-path functions marked @inline(__always); wrapping arithmetic (&+) avoids overflow traps
  • Console output batched to main thread; capped at ~100K chars to bound memory
  • Crypto ops (AES/SHA) designed to route to hardware/CryptoKit in production

On-device AI

The architecture reserves CPUID leaf 2 feature bits and the 0xFF opcode escape for future neural-engine dispatch. The app is structured so an ANE-backed matrix-multiply uop can be added without changing the ISA.

5. How It Was Built

Step 1 — Architecture (docs/ARCHITECTURE.md)

Started from the constraint "not RISC". Chose a stack machine because it's the most fundamentally different execution model that's still practical: zero-operand ALU, hardware stacks, variable-length encoding. Specified 4 stacks, 15 registers, 4 privilege levels, and a 3-level MMU. Every modern feature (SIMD, crypto, atomics, perf counters, debug) was adapted to stack semantics rather than copied from RISC designs.

Step 2 — Instruction Set (isa/ISA_REFERENCE.md)

Allocated the 256-opcode space by category. Stack ops in 0x00–0x3F, ALU in 0x40–0x7F, etc. Immediate sizes encoded in the opcode mnemonic (PUSH8/16/32/64). Branch offsets are PC-relative; calls push to the call stack. Documented stack effects for every instruction in a b → c notation.

Step 3 — Microcode (microcode/MICROCODE.md)

Defined a micro-operation set (DPUSH/DPOP/ALU/LD64/BRANCH/TRAP…) and wrote the expansion for every multi-uop instruction: ENTER/LEAVE frames, CALL/RET, MEMCPY's chunk+tail loop, SHA-256's 64 rounds, trap entry/exit. This is the contract the VM implements.

Step 4 — Assembler (novas.py)

Two-pass assembler: pass 1 collects labels and computes addresses; pass 2 emits bytes with PC-relative branch resolution. Verified with hello.nova (51 bytes) and fib.nova (121 bytes).

Step 5 — iOS VM App (vm-app/)

Swift implementation of the fetch-decode-execute loop following the microcode spec. NovaMemory owns guest RAM; NovaCPU implements every opcode; NovaVMEngine bridges to SwiftUI. Menu → file picker → run → console. Firmware toggle wired to either the built-in image or a user-supplied binary.

Step 6 — Verification

  • Assembler: both example programs assemble without errors; branch offsets resolve correctly
  • Architecture: every instruction's stack effect documented and cross-checked against microcode
  • App: code reviewed for Swift correctness (optionals, thread boundaries, security-scoped URLs)
  • Not yet done: on-device test run, which requires Xcode build + install
