## Coverage added (24 opcodes; total compiled now 81 of 93 —
recounting J2's operand table gives 57 stack+ALU, its note's
"56" notwithstanding)

- **Memory (9):** LOAD8 80, LOAD64 83, LOADU8 84, LOADU16 85,
  LOADU32 86, STORE8 87, STORE16 88, STORE32 89, STORE64 8A.
- **Control flow (12):** JMP A0, JMP32 A1, BZ A2, BNZ A3, BEQ A6,
  BNE A7, CALL A8, CALL32 A9, CALLI AA, RET AB, JMPI AC, LOOP AD —
  all block terminators (reason `.next`, dispatch at the resolved
  target; no in-cache chaining — dispatch goes through the
  trampoline, which is the design's §6.2 form). Direct targets are
  baked at compile time with step()'s wrapping pc+offset
  arithmetic; RET/JMPI/CALLI dispatch on the popped runtime value.
  CALL/CALL32/CALLI push the return pc (nextPc) through the same
  checked cpush sequence as J2, so call-stack limit traps
  (stackOverflow / storeAccessFault, pc = nextPc) are step()'s.
  BEQ/BNE read the guest Z flag from JitState.flags (bit 2 of the
  packing), never the host NZCV.
- **TRAP AE (1):** compiled as a fault exit per §6.3 — baked
  operand byte written to tval, then the `.fault` stub for
  `breakpoint` with pc = nextPc; the trampoline hands it to
  handleTrapAfterStep unchanged.
- **DSPSET 12 / CSPSET 1E (2):** the design's terminate-after form
  (superseding J2's single-step treatment): pop into the live
  dsp/csp register, exit `.next` at nextPc, and the block record's
  `endFlushes` makes the trampoline drop the whole cache (rule
  J2) before re-dispatching.

## Peek-exit set (exit BEFORE the instruction, single-stepped)

Runtime peek-exits (the DIV/REM D2 bail shape: boundary check
only, peek don't pop, `.singleStep` with delta excluding the
instruction, then step() performs it and J5 flushes):

- **LOAD64 83 / LOADU8 84 / STORE8 87 / STORE64 8A whose popped
  address is >= 0xFFFF_FFFF_FFFF_0000** — the four MMIO-routed
  opcodes, rule J3. The peek branches to the inline RAM body
  whenever the stack slot is unreadable (underflow/access), so
  those states fault through the body's pops in step()'s order.
  Console stores therefore still pay one exit + flush per
  character (design's deliberate cost; D3 unchanged).
- Everything in this set is a *runtime* decision, not an opcode:
  the same opcode with a RAM address executes fully inline.

Compile-time bail set (block ends BEFORE, single-stepped, J5
flush) — unchanged in kind from J2, listed for completeness:

- **MEMCPY 8F** — design §6.5: unbounded write range; J1 cannot
  check it cheaply inline. (Decision: it does NOT join the inline
  stores; the single-step + flush is exact by construction.)
- **ROLL 0F** — design bail (as in hotloop/J2).
- **Unimplemented opcodes in the J3 ranges** — 81, 82, 8B–8E and
  A4, A5 (and AF): step() sets tval = opcode and throws
  illegalInstruction; single-stepping reproduces that by
  construction.
- **All remaining J4 groups** — CSRSET C7, MRET C2, ECALL C0,
  EBREAK C1, WFI C5, CSRGET C6, RDCYCLE CC, RDTIME CB, RDRAND F4,
  CPUID F5: still foreign (block ends before, single-stepped).

No access class had to be demoted from inline to peek-exit for
boundary reasons: every implemented load/store width is checked
with the accessor's own single comparison (addr < ramSize for
1-byte, addr <= maxStart16/32/64 otherwise), so an access faults
iff any byte is out of bounds — including accesses spanning the
RAM end (part RAM / part out-of-bounds) and non-routed opcodes
aimed at the MMIO page (LOAD8/LOADU16/LOADU32/STORE16/STORE32
there fault with load/storeAccessFault exactly as step() does).
An access starting below the MMIO base but reaching into it is
impossible to route in step() either (routing tests the start
address only) and faults on the RAM check in both engines; an
access starting in the MMIO page in a routed opcode is
peek-exited whole to step(), never split.

## Invalidation implementation notes (STORE / SMC core)

- Every compiled RAM store (STORE8/16/32/64) emits, immediately
  after the store completes, the same 3-compare interval check
  J2 built for STORL: [addr, addr+size) vs the cache bounding
  interval [codeLo, codeHi) read live from JitState (refreshed by
  the trampoline before every dispatch). On any possible overlap
  the block exits `.invalidated` (pc = nextPc; the store's
  semantics are complete) and the trampoline drops the WHOLE
  cache and re-dispatches fresh. The store's own bounds check has
  already bounded addr to RAM, so addr+size cannot wrap.
- STORL keeps its J2 inline check unchanged.
- Stack pushes remain unchecked (rule J2 premise — the compiler
  still refuses any instruction overlapping a stack region, and
  DSPSET/CSPSET now flush after executing).
- selfmod is the gate proof: nativeInstructions=53,
  singleSteps=8 (the 7 console MMIO stores + WFI), sum = the
  golden 61 cycles, console `SCBDEK\n`, PASS. Phase 1a's patch
  store hits the J1 check inside its own block (the patched
  PUSH8 recompiles); phase 2's patch store overlaps the bounding
  interval of the cached loop block (whole-cache drop, iteration
  2 recompiles and prints E).

## Deviations / exclusions (with reasons)

1. **No in-cache target chaining.** §6.2 specifies `.next` exits
   with trampoline dispatch at nextPc; chaining is named in the
   lane scope only "if the design specifies it" — it does not.
   Every terminator returns to the trampoline, which is also what
   keeps the per-dispatch limit/timer recomputation exact.
2. **TRAP AE compiled now** (a §6.3 trap exit, pulled forward
   from J4's list) because it sits inside the 0xA0–0xAE range the
   lane covers and its semantics is exactly the §5.2 fault exit
   J2 already built. ECALL/EBREAK/WFI were NOT pulled forward —
   they are outside the J3 ranges.
3. **CSRSET/MRET remain single-stepped** — J4 system group, as
   designed; only DSPSET/CSPSET (named in the J3 scope) got the
   terminate-after form.
4. **MEMCPY stays a bail** (see peek-exit set) — per design §6.5,
   not a J3 demotion.

## What J4 must know

- 81 of 93 implemented opcodes now compile. The remaining 12 are
  exactly the J4 system set: ECALL C0, EBREAK C1, MRET C2, WFI C5,
  CSRGET C6, CSRSET C7, RDTIME CB, RDCYCLE CC, RDRAND F4, CPUID
  F5, plus the two named bails ROLL 0F / MEMCPY 8F — no other
  foreign opcodes exist among the implemented set. Foreign-head
  single-steps in the gate stats are now: MMIO instances, WFI,
  and RDTIME (bench/console sections).
- Terminator plumbing J4 can reuse: `endIsTerminator` (exit stub
  writes state.pc, trampoline re-dispatches, no single-step),
  `endFlushes` (post-execution whole-cache drop — CSRSET/MRET
  need the same shape if compiled as terminators: execute, exit,
  and the trampoline already recomputes the §5.3 limit from
  entry status at every dispatch, so a status writer only needs
  the terminate half, not a flush, unless it also writes RAM).
- The `.fault` stub shape already carries TRAP; ECALL/EBREAK are
  the same emission with no tval write (EBREAK) / ecallU rawValue.
- galaxy/console speed is now bounded by the MMIO peek-exit +
  J5 flush per character (bench console section above) — that is
  the D3 measurement the design deferred to J4's table.
- All J2 invariants were preserved and re-proven by this gate:
  unified limit register, trap-state reconstruction (fault pc =
  nextPc everywhere, including the new stack-touching control
  forms), flush points (trap J4, single-step J5, per-run J6,
  DSPSET/CSPSET J2), failedHeads memo cleared by every flush, and
  the exclusivity discipline (no step()/trap call inside
  withHotBuffer — compilation and the generated-code call remain
  the only in-buffer work; nothing in J3 changed that boundary).
