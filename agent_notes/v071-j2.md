## J2 exclusions (block ends BEFORE the instruction; single-stepped)

- **ROLL 0F** — design §6.5 bail, as in hotloop.
- **DSPSET 12 / CSPSET 1E** — the design (§6.2) terminates the block
  AFTER executing these and flushes (rule J2); J2 instead ends the
  block BEFORE them and single-steps (+ J5 flush). Observable
  semantics are identical; the design's terminating form is a
  performance refinement J3 can adopt when it lands its other
  terminators. Reason: a moved stack pointer invalidates the
  compiler's stack-region premise, and the single-step path makes
  that safe by construction rather than by a post-execution flush
  argument inside generated code.
- Everything in the J3/J4 groups (memory, control flow, system,
  trap/halt exits, RDTIME/RDRAND helpers) — unchanged from the
  design's lane split.

## Exactness machinery implemented

- **JitState offsets verified, not assumed** (J1 awkwardness 4):
  `JitOff.verifyLayout()` compares `MemoryLayout.offset(of:)` for
  every field generated code touches against the design constants
  at every trampoline entry; any mismatch declines the run before
  a single guest instruction executes.
- **Boundary sequence per instruction** (§5.2/§5.3): limit check,
  then limit -= 1 / delta += 1, in step()'s fetch position. The
  limit is the unified min(blockCount, timerAllow, budgetAllow)
  computed per dispatch; budget wins ties; the winning reason is
  passed through JitState.limitReason because blocks are cached
  across dispatches with different winners.
- **Exit stubs for every class J2 blocks can produce:** .next
  (fallthrough-to-foreign and 64-cap forms), .fault (per-site stubs
  baking the faulting instruction's nextPC + trap rawValue into
  exitAux; tval written inline where step() writes it — PUSHR/POPR
  n ≥ 16), .singleStep (signed DIV/REM D2 bail, pc at the
  instruction, delta excluding it so step() redoes the timer check
  and fetch exactly once), .timerLimit / .budgetLimit (per-boundary
  stubs naming the un-executed instruction's pc), .invalidated
  (STORL J1 overlap). .wfi is handled in the trampoline for
  contract totality but cannot be produced by J2 blocks (WFI is
  foreign). Every stub folds through the common path: cycle +=
  delta, dsp/csp/fp stored back, lastDelta recorded, nextPc = pc,
  callee-saved registers restored.
- **Timer settling:** after every block the trampoline subtracts
  delta from memory.timerCount when the block was entered armed
  (delta ⊦ begun instructions, faulting one included, bailed one
  excluded); on .timerLimit it then resets the countdown to the
  interval, counts one firing pseudo-step (hotRun parity), flushes
  (J4) and calls handleTrapAfterStep(.timerInterrupt). The
  timerCount == 0 && armed corner is emulated at dispatch, never
  entered into a block.
- **Trap bridging:** .fault syncs out, flushes (J4), then calls the
  interpreter's own handleTrapAfterStep via the NovaCPU bridge —
  no second trap implementation exists.
- **Invalidation skeleton:** whole-cache drops at every J4 point
  (fault exits, timer firings), every J5 point (after EVERY
  trampoline single-step — this is what makes selfmod pass: all of
  its stores are foreign STORE8s, each followed by a flush, and
  phase 1a's patched PUSH8 is only reached after its store
  single-stepped), STORL's inline J1 interval check (the one store
  in the J2 groups), and J7 pool exhaustion (flush + recycle).
  Blocks are per-run (J6) and the compiler refuses any instruction
  overlapping a stack region (J2 premise).

## Stats counters (definitions)

- `blocksCompiled` — blocks successfully emitted + written to the
  pool this run.
- `blockEntries` — generated-block invocations.
- `nativeInstructions` — guest instructions executed in generated
  code (sum of block deltas; a faulting instruction counts, a
  bailed one does not).
- `singleSteps` — instructions executed via step() on the JIT's
  behalf.
- `faultExits` / `limitExits` — block returns of those reasons
  (limitExits counts budget + timer limit exits, plus the
  defensive timerCount==0 firing emulation).
- `invalidations` — whole-cache drops that discarded ≥ 1 block.

## Deviations from the design (with reasons)

1. **JitState appended slots (offsets 304–344)** — `jitLimit`,
   `dslim`, `cslim`, `dataStackBase`, `callStackBase`,
   `limitReason`. §5.1's layout (0–296) is byte-unchanged; the
   design gives generated code no slot for the per-dispatch limit,
   for the stack limits/bases its push/pop checks compare against,
   or for the per-dispatch limit-exit reason (which cannot be
   baked into a cached block). Carrying them in the state block
   keeps the block signature exactly §5.1's
   `(state) -> exitReason`.
2. **DSPSET/CSPSET single-stepped** instead of compiled as
   terminators — see Exclusions.
3. **POPCNT is a SWAR sequence**, not CNT+fold: it needs only the
   basic integer encodings, all of which were cross-checked against
   clang's assembler during development (37/37 emitter forms
   byte-identical; the SWAR algorithm itself verified against
   Python's bit_count on 100k random inputs).
4. **NovaCPU ADDITION 4** (two bridge methods) — forced by Swift
   access control, enumerated in the variant's banner.

## What J3 must know

- The trampoline skeleton is complete: cache, flush points,
  single-step accounting, timer/budget limit protocol, trap
  bridging and stats all exist and are exercised. J3's work is
  compiler-side: add the memory group (reuse emitLoad64/
  emitStore64 shapes, add the other widths + the MMIO peek-exit —
  a new stub kind or reuse .singleStep with pc at the instruction,
  delta excluded: note the peek must run BEFORE the boundary
  commit, exactly like the DIV bail), the control-flow terminators
  (.next with a computed/baked target is already the stub shape —
  state.pc is the only dispatch input), and DSPSET/CSPSET (either
  keep the J2 single-step treatment or implement the design's
  terminate-then-flush: the flush helper is already there).
- STORL's J1 check reads codeLo/codeHi from JitState at block
  runtime; the trampoline refreshes them from the cache interval
  before every dispatch. J3's stores should reuse that exact
  sequence.
- Blocks whose head fails compilation are memoised in failedHeads
  only until the next flush (flushCache clears it) — byte changes
  always arrive with a flush in this design, so this is safe, and
  J3 must preserve the invariant "no guest-byte change without a
  flush" rather than the memo itself.
- The 4 MiB pool recycles on exhaustion with a full flush; block
  size worst case is PUSHALL/POPALL-heavy (~150 words per guest
  instruction, ~38 KB per 64-block), so recycling is a cold path.
